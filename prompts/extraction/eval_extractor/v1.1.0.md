Convert the following network-traffic explanation into a structured list of
atomic claims. You are a parser, not a judge: report what the text itself
claims, not whether it is correct about the traffic and not what you can infer
about it.

Explanation text:
{{explanation_text}}

Feature vocabulary (use these exact names):
{{feature_vocabulary}}

List every feature the text makes a claim about, with the direction the text
asserts:

- `"+"`: the text says the feature raises / pushes up the score for the class it argues for
- `"-"`: the text says it lowers / pushes down that score
- `"unclear"`: the text names the feature but gives no explicit directional evidence

Only give `"+"` or `"-"` when the text gives explicit evidence of the direction.
The text must say something about the feature's *effect*: that it increases,
raises, lowers, reduces, drives, contributes to, adds to, weakens, or otherwise
moves the score, or give a signed value for it.

Describing the feature's value is not a directional claim. "A high PSH Flag
Count (1.0) suggests potential payload manipulation typical of botnet activity"
says the value is high and reads it as suspicious; it does not say the feature
raises the score. That is `"unclear"`. So is "unusually large", "within normal
bounds", "consistent with automated traffic", unless the sentence also states
the effect on the score. If you find yourself inferring the direction from what
the feature *means* rather than reading it in the text, the answer is `"unclear"`.

Use the canonical name from the vocabulary even when the text paraphrases it
("maximum forward packet length" -> `Fwd Packet Length Max`). Leave out anything
that is not a vocabulary feature, and leave out features the text does not
mention.

For each claimed feature, emit one JSON object with these keys:
- `feature`: the canonical vocabulary name;
- `direction`: `"+"`, `"-"` or `"unclear"`, as defined above;
- `rank`: the 1-based order the text gives the feature, or null if unordered;
- `magnitude`: any numeric magnitude the text attributes, or null.

Return only a JSON array of these objects, in order of first mention. If the
text claims nothing about any vocabulary feature, return `[]`.
